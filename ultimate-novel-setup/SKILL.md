# 小说项目初始化

把现有目录整理成能够持续写作和恢复的小说项目。只创建当前确实需要且尚不存在的内容，不覆盖正文、设定、作者手改和其他 Agent 的工作。

纯目录检查、文件盘点和机械补缺不加载价值判断。需要记录或判断作者意图、人物、世界和读者体验时，完整读取 [小说质量核心](../ultimate-novel/references/reader-experience-first.md)；只记录作者已明确表达的方向，不从一般社会观念推导项目立场。

## 开始前

1. 确认成品目录，而不是把小说写进 Skill 或工具目录；
2. 盘点现有正文、设定、大纲、追踪和版本文件；
3. 识别长篇、短篇和仅需局部返修的项目规模；
4. 只创建缺失且会被当前工作实际使用的部分；
5. 现有同名文件先读取，不覆盖、不清空、不移动。

## 项目规模

长篇或需要持续续写的项目，读取 [项目状态结构](../ultimate-novel/references/project-state-schema.md)，按实际需要建立正文、设定、大纲和追踪职责。

单篇短文只保留原稿、版本、作者要求和必要审改位置，不创建卷纲、时间线、伏笔、章节事实等长篇体系。作者只要整理现有文件时，不自动生成正文、设定和大纲内容。

## 文件职责

- `设定/作者长期意图.md`：作者确认的目标体验、人物边界和硬禁区；
- `设定/角色/`：人物卡，主要人物包含说话习惯，格式见项目状态结构；
- 正式总纲、卷纲和细纲：已采用的未来计划；
- `大纲/候选推演/`：尚未采用的重大走向；
- `大纲/候选推演/暗线表.md`：主角不在场时重要人物和势力的后台推进，不是正史；首次需要暗线推演时才创建，规则见 [世界运转与暗线推演](../ultimate-novel/references/world-offscreen-progress.md)；
- `正文/`：正式章节与作者明确保留的版本；
- `追踪/章节事实/`：已正式提交正文确认的事实；
- 角色状态、时间线和伏笔：只增量记录会影响后续写作的当前状态；
- `追踪/卷摘要.md`：每卷结束后写的本卷摘要，用来找回旧事，第一卷结束时创建；
- `追踪/写作断点.md`：恢复当前任务所需的最小现场；
- `追踪/项目经验.md`：经数据、审稿或作者确认验证过的做法，由 review 和 performance-review 写入。

不建立第二套日志、索引、变更记录或重复状态系统。现有项目已有同等职责文件时复用，不为统一命名搬迁作者结构。

## 候选未来隔离

未决定的重大走向放入候选区。作者明确采用后才更新正式大纲和追踪文件；未采用方案不得写成已经发生的正史。

## 冲突处理

作者本轮明确要求优先；若会推翻现有正史，先指出具体冲突并让作者裁决。已确认事实、时间线和硬禁区优先于风格与参考案例。不设僵硬的固定加载队列，按当前任务读取最小充分材料。

## 完成检查

- 没有覆盖、移动或删除现有文件；
- 没有把候选写进正史；
- 没有自动生成作者未要求的正文；
- 没有为目录整齐创建空模板；
- 没有创建开发日志、额外索引、变更记录和重复状态系统；
- 新建文件的职责清楚，能够从写作断点恢复。
