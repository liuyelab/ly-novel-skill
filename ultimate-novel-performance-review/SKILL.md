# 发布后数据复盘

从真实数据中找到最早出现异常的环节，再判断读者在此处失去了什么承诺、期待或回报。数据用于缩小问题范围，不证明唯一因果，也不证明某种价值立场错误。

提出诊断或返修方向前完整读取 [小说质量核心](../ultimate-novel/references/reader-experience-first.md)。需要当前后台、榜单或页面证据时先加载 `ultimate-novel-market-data`；本模块不复制取数流程。

## 输入与口径

优先使用平台原始字段、时间范围、作品版本、推荐轮次、章节发布时间、修改记录和相关评论。没有可比基线时明确说明，只做候选解释。

区分曝光、点击、进入阅读、有效阅读、追读、完读、收藏、转化和收益。不同平台同名指标不默认同口径；截图和单日波动不能自动证明长期趋势。

## 最早异常原则

沿读者路径寻找最早显著异常：

| 节点 | 先问的读者问题 |
|---|---|
| 曝光不足 | 是否根本没有获得足够分发，暂时不能评价正文 |
| 点击低 | 包装是否没有形成清楚、有差异且可信的承诺 |
| 首章流失 | 正文是否没有及时兑现包装承诺或让人物进入具体处境 |
| 前三章下降 | 冲突、目标、人物选择或第一次回报是否不足 |
| 中段下降 | 是否重复、目标停滞、人物失真或长期没有新期待 |
| 某章突降 | 是否承诺落空、信息断裂、逻辑冲突、表达失真或断章问题 |
| 转化低 | 付费或关注节点是否没有形成足够未完成价值 |

上游异常没有排除时，不把下游数字直接归因于正文。

## 诊断

1. **结论先行**：指出最早异常节点、严重程度和当前把握；
2. **证据与替代解释**：列支持证据、相反证据、样本限制及其他可能原因；
3. **读者损失**：说明读者在此处失去的承诺、人物、期待、清晰度或回报；
4. **最小修复**：提出直接针对根因、能独立观察效果的最小改动；
5. **复测**：明确指标、观察窗口、可比版本和返回哪个专业模块。

评论只作为证据之一。高频评论、数据断点和正文证据相互支持时提高把握；单条强烈意见不自动代表多数读者。

不得用 AI 的合法、善良、正确、平衡和稳妥偏好解释流失。只有真实读者行为、评论和正文因果共同支持时，人物立场或价值表达才进入候选原因。

## 修复边界

- 点击问题可路由到 `ultimate-novel-cover`；
- 开篇、结构、人物和兑现问题路由到相应写作模块；
- 逻辑、连续性和正式提交判断路由到 `ultimate-novel-review`；
- 局部模板感和对白问题路由到 `ultimate-novel-deslop`；
- 方向本身需要重评时回到 long-scan 或 short-scan。

本模块只提出返修方向，不默认直接改正文。重大调整时比较继续观察、局部修复和重开三种成本，由作者决定。

## 复测与经验

改动后使用可比时间窗、流量来源和章节版本观察同一指标。数据没有改善时撤回因果结论，检查替代解释，不在失败方向上继续扩大改动。

只有可比数据、读者反馈和正文证据共同支持时，才把方法记入项目 `追踪/项目经验.md`（格式见项目状态结构），供写作、对标和润色模块读取。一次推荐失败、短期波动和检测分数不能证明整本书必须重写。

## 输出

先给最早异常和把握，再给证据、替代解释、读者损失、最小修复、复测方法和返回模块。没有足够数据时明确说不能确认，不为完整格式制造结论。
